## State

Everything of the card is built except the backup CronJob, which the human moved out of phase 2 with the backup through the admin port.

- `deploy/tier1/`: the ConfigMap (the `zoe.toml` of the server: `admin-listen`, `shutdown-timeout = "30s"`, `log-format`), the StatefulSet (one replica, `OrderedReady`, a volume claim template on the class `ssd`, `terminationGracePeriodSeconds: 45`, a startup probe and a liveness probe on `/healthz`, a readiness probe on `/readyz`), the Service `zoe` on the ZEO port, the headless Service `zoe-admin` on the admin port, the ServiceMonitor and the PodDisruptionBudget with `maxUnavailable: 0`. - `deploy/pyproject.toml` and `deploy/uv.lock`: the environment of the tests (pytest, PyYAML). `just deploy check` runs `deploy/tests`. `just test` runs `just deploy check` at its end, so CI runs the acceptance test. `just check` lints `deploy/` with ruff.

## What fails

`deploy/tests/test_tier1.py::test_the_backup_job_backs_up_restores_and_verifies` needs exactly one CronJob that runs `zoe backup --admin`, `zoe restore` and `zoe verify`. `zoe backup` has no `--admin` option in phase 2, and the human decided that the phase 2 manifests ship no backup CronJob. So the test fails with `AssertionError: no CronJob`. The other tests of the file are expected to pass; they were not run locally (CI runs them).
