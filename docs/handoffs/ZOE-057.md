# ZOE-057 handoff: shared blob directory, storeBlobShared

## State

The implementation is complete on `card/ZOE-057`. Four of the five cases of the acceptance test `python/zoedb/tests/server/test_shared_blob_dir.py` pass. The fifth, `test_clients_write_and_read_blobs_in_the_shared_directory`, cannot pass as written, because of a fault in the test itself. The builder did not edit the test.

- `Txn::store_blob_shared` (zoe-core, `commit/mod.rs`) and `BlobStore::take_shared` (`blob/mod.rs`) take the file of a client in the directory of its oid by rename. The name must have no `/` or NUL and end in `.tmp` or `.tmp-`. The call syncs the file, the parent of each level of the oid directory and the oid directory, then renames the file into `blobs/tmp/`.
- The crash simulation has a new case, `every_crash_image_of_a_shared_blob_opens_without_an_orphan`. It fails when the level syncs are removed.
- `zoe serve --shared-blob-dir` (`ZOE_SHARED_BLOB_DIR`) accepts `storeBlobShared`. At its start, the server writes the layout file of each blob directory that is not read-only. `zoe serve --blob-dir` (`ZOE_BLOB_DIR`) sets the blob directory of the store of `--path`. Both are keys of the configuration file.

## What failed

`write_blob` in the acceptance test returns `conn.root()[name]._p_serial` from a new transaction. ZODB's `Connection._store_objects` calls `obj._p_invalidate()` on a blob after `storeBlob`, and `Connection.tpc_finish` does not update the serial of a ghost. So the blob is a ghost with the serial `z64`, and the test looks for `0x00.blob`, which no server writes. A stock ZEO server gives the same result, because the serial comes from the client.

The server writes the blob at the correct path. A copy of the test with the edit below passes all 5 cases.
