## What failed

`a_crash_during_creation_can_leave_an_unreadable_file` shows that a crash while redb creates a database can leave a zero-filled file that redb refuses to open ("magic number mismatch"). The store opens without a repair step only if it creates its database atomically: write it under a temporary name, sync it, rename it into place, sync the directory. `MemVfs` has no rename and no directory sync yet.

## Questions for the human (stop-and-ask: on-disk format)

1. Tables and keys. Proposal: the four key spaces of the data model as redb tables. `records`: key `(oid, tid)`, value the record frame. `txns`: key `tid`, value the transaction frame. `blobs`: key `(oid, tid)`, value the blob frame. `meta`: fixed text keys (`format` = `ZOE format 1`, `last_tid`, `next_oid`, `pack_watermark`). Keys are big-endian `u64`, as the specification says.
2. The branch id. The feature triage says that it is "reserved in the key layout", while N19 says that "every record carries" it. Does it go in the key (a prefix: `(branch, oid, tid)`) or in the record header? How wide is it: `u16`, `u32` or `u64`?
3. The record frame. The specification gives `flags | length | checksum | payload` with xxh3-64, plus a codec byte, a branch id, a typed-field-slot header and the previous serial. Proposal, little-endian header:

   | Offset | Size | Field |
   | --- | --- | --- |
   | 0 | 1 | frame version |
   | 1 | 1 | flags (compressed, encrypted) |
   | 2 | 1 | codec (0 none, 1 zstd, 2 zstd with the store dictionary) |
   | 3 | 1 | reserved, 0 |
   | 4 | 4 | branch id (if it is not in the key) |
   | 8 | 8 | previous serial |
   | 16 | 4 | payload length |
   | 20 | 2 | typed-field-slot header length (0: no slots) |
   | 22 | 2 | reserved, 0 |
   | 24 | 8 | xxh3-64 of bytes 0 to 23, the slots and the payload |
   | 32 | n | typed-field slots, then the payload |

   Does the checksum cover the header? Little-endian or big-endian? The specification gives no meaning for the typed-field-slot header yet: is a length field, always 0 for now, enough room?
4. The store directory. Proposal: `zoe.redb` (the database), `blobs/` (the blob tree), `lock` (the single-writer lock). Create `zoe.redb` atomically, as in "What failed". Take the single-writer lock with `flock` on `lock`. Is that the layout?
