# ZOE-069 handoff: the Plone test suites in both modes

## State

The wiring is done and works in both modes. The acceptance test `plone/tests/test_plone_suites.py` is red for two reasons that do not come from the storage. Both need a decision of the human.

- `python/zoedb/src/zoe/plone/testing.py`: the layers `ZoeStorage` (a `zoe.Storage` in a new directory) and `ZoeServe` (a `ZEO.ClientStorage` of `zoe serve`). `install()` makes the layer a base of `plone.testing.zope.STARTUP`. While the layer is set up, `plone.testing.zodb.stackDemoStorage(None, name)` returns a `DemoStorage` whose base is the ZOE storage, with `close_base_on_close=False`. A call with a database does not change.
- `plone/base.cfg`: the part `test` (zc.recipe.testrunner) with the test extras of the three packages. `zoe.cfg` and `zeoclient.cfg` give its `initialization`.
- `just plone <scenario> suites [bin/test options]`: on filestorage (the stock baseline), zoe and zeoclient. The zeoclient run starts `zoe serve` on a new store and a free port, passes the address in `ZOE_PLONE_ZEO_ADDRESS`, and stops the server with SIGTERM at the exit.
- `ci/`: the function `plone` runs `just plone zoe suites`, then `just plone zeoclient suites`.
- `plone/tests/test_suites_layer.py`: a selection of 5 tests in each mode, the stop of the server after a failed `bin/test`, and a probe of the layer in the interpreter of the zoe instance.

## What fails

1. The 5 errors are the Latin-1 tests of `Products.CMFPlone.tests.testUnicodeSplitter` (`testNormalizeLatin1`, `testProcessLatin1`, `testMixedModeQuery`, `testQueryByLatin1`, `testQueryByLatin1Lower`): `ValueError: Unsupported locale`. The interpreters of the devenv shell know only the C locales and `en_US.utf8`. `just plone filestorage suites -m testUnicodeSplitter` gives the same 5 errors on the stock storages. With `LOCALE_ARCHIVE` set to a full `glibcLocales` archive, the 25 tests of the module pass on the zoe layer.
2. The floor of the acceptance test is 3000 tests. The three suites hold 2975 tests at the default level of zope.testrunner (`bin/test --list-tests`). `--all` lists 3114: the other 139 are the robot tests of Products.CMFPlone and plone.app.contenttypes, which need a browser.

No test fails or skips because of the storage. The 26 skips have static conditions in the suites: the Plone version, an optional package that is not installed, or a test that is not implemented.

## Tried

- The locale archive of a store path in `/nix/store` fixes the 5 errors. That is not reproducible, so the branch does not use it.
