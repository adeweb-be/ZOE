# ZOE-062 handoff

## State

TLS on the ZEO port is built: `--tls-cert`, `--tls-key`, `--tls-client-ca` and `--tls-read-only-client-ca`, with their `ZOE_*` twins, the keys of the configuration file and of the `<zoe-server>` section. `just check` is green. The acceptance test `python/zoedb/tests/server/test_tls.py` passed on CPython 3.12 (4 of 4). On CPython 3.14t, 4 of 4 tests failed.

## What failed

The failure is in the certificates that the acceptance test makes, not in the server. From CPython 3.13 on, `ssl.create_default_context` sets `VERIFY_X509_STRICT`. OpenSSL then refuses a CA certificate without the keyUsage extension: `CERTIFICATE_VERIFY_FAILED: CA cert does not include key usage extension`. `openssl req -x509` with the default configuration (OpenSSL 3.6.4 in devenv) writes no keyUsage. So the client refuses the server certificate before ZEO starts, and the server logs `tls handshake eof`.

## What I tried

A copy of the test outside the repository, with one added line in `make_ca`, passed 4 of 4 on CPython 3.13 and 3.14t:

    "-addext", "keyUsage = critical, keyCertSign, cRLSign",

after the `-out` argument of the `openssl req -x509` call. Nothing on the server side can change this: the client checks its own trust anchor.

## Next step

Resolved: the human approved the keyUsage line on the card, and it is committed on `card/ZOE-062`. The review then asked that a read-only client may not pack; `Session::pack` refuses it with `ReadOnlyError`.
