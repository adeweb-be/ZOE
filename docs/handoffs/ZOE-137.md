# ZOE-137 handoff

## State

- Branch `card/ZOE-137` holds the acceptance-test skeleton, a merge of `origin/main`, and the whole change of the card.
- The store keeps `object_count` in `meta`. The format name is `ZOE format 2`. A new store starts at 0. The first writer open of a store of `ZOE format 1` counts the oids of `records` once and writes the count and the new name in one write with a sync. A read-only open of a store of format 1 writes nothing and gives `None`. A store of format 2 without the row fails with `Format`.
- `len(zoe.Storage)`, the `length` of `get_info`, of `info` after a commit and after a pack, and of `get_size_info` give the count. `zoe verify` compares the count with the oids of the records.
- ADR 0033, the specification, and the `CLAUDE.md` files of zoe-core, zoe-py, zoe-server and zoe-convert describe the change.
- Unit tests: `crates/zoe-core/tests/object_count_writes.rs`, `session.rs` (`the_length_is_the_object_count_of_the_store`), `zoe-convert` `verify.rs` (three tests), `cli/verify.rs` (one test).

## What fails: the acceptance test has a malformed pickle

Six of the nine tests of `crates/zoe-core/tests/object_count.rs` pass. The three tests that pack fail:

```
Format("pack cannot read the references of the record of oid Oid(0), tid ...: cannot decode at offset 58: a text argument has no newline")
```

The constant `PICKLE` of the test is

```
b"\x80\x03cpersistent.mapping\nPersistentMapping\nq\x00.\x80\x03}q\x01X\x04\x00\x00\x00datag\x01s."
```

After `X\x04\x00\x00\x00data` comes `g\x01`. `g` is the text opcode GET, whose argument is a decimal number that ends with a newline. Here no newline follows, so `zoe_pickle::persistent_ids` refuses the record. The pack with garbage collection reads the references of each record that it marks, and an invariant of the core makes such a refusal a hard error (`Format`) before the pack removes anything. The core is right, and the test is wrong. The intended opcode is `h\x01`, BINGET 1.

With that one byte changed locally (`g` to `h`), all nine tests pass:

```
test result: ok. 9 passed; 0 failed; 0 ignored; 0 measured; 0 filtered out
```

The change was reverted. The branch holds the test as the planner wrote it.

## The question

May the builder change one byte of `PICKLE` in `crates/zoe-core/tests/object_count.rs`, `datag\x01s.` to `datah\x01s.`? Nothing else in the test changes.

## Other points for the reviewer

- **The count is decided in the backend write, not at the vote.** The card says that the finish decides the new oids under the commit sequencer, with the vote and the notes of the pack. The redb write reads, for each oid that it puts or removes a record of, if the oid has a record, under the commit sequencer. So a pack batch between the vote and the finish is seen without notes. ADR 0033 gives the reason. A unit test covers that case.
- **Outside the scope fence.** `crates/zoe-server/src/cli/verify.rs`: the report of `zoe verify` prints the count, the line "the store has no count yet" for format 1, and the finding. The JSON gets the keys `object_count` and `count`. The card asks for that line, and only this file prints it. The specification paragraph of `zoe verify` is updated too.
- **`zoe.Storage(read_only=True)`** opens the store for writes in the core (an invariant of zoe-py), so it upgrades a store of format 1. Only `zoe serve --read-only` and the tools use the read-only open of the core, and they give 0.
