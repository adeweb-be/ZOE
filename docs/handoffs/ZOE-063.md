# ZOE-063 handoff: the ZEO test harness

## State

The branch `card/ZOE-063` has the harness, inside the scope fence:

- `python/zoedb/src/zoe/testing.py`: `ZeoLayer` and `ZEO_LAYER`. `setUp` replaces `start_zeo_server` in `ZEO.tests.forker` and `ZEO._forker`. The replacement reads the ZEO configuration with `ZConfig.schemaless`, maps each storage section to a ZOE store (same name, same blob directory, the path of a `<filestorage>`, a new directory for a `<mappingstorage>`), writes a TOML file for `zoe serve --config`, and starts `zoe serve` through `ZoeServer`. `address`, `invalidation-queue-size`, `read-only` (of `<zeo>` and of `<filestorage>`), `client-conflict-resolution`, `msgpack true` and `create` are taken. Any other key or section fails the start with a `ValueError` that names it. `tearDown` kills every server and puts back ZEO's functions.
- `python/zoedb/tests/conformance/test_testing.py`: 12 unit tests of the layer.
- `justfile`: `just conformance` builds the `zoe` binary and sets `ZOE_BINARY`.
- `ci/src/ci/main.py`: the docstring of `conformance`.

The first acceptance test, `test_the_forker_of_zeo_starts_zoe_serve`, passes. The unit tests pass. `just check` passes.

## What fails

`test_the_storage_mixins_of_zeo_pass_against_zoe_serve` fails against the `zoe` binary of `main`. 33 of the 39 selected tests pass. 6 fail, for two gaps of `zoe serve`, not of the harness:

1. `storea` with a serial of `None`. A stock `ClientStorage.store` sends the serial that the test gives, and ZODB's mixins store a new object with `revid=None`. `zoe serve` stages the call and fails the vote with `TypeError: an oid or a tid is not bytes`. A ZEO server with a FileStorage accepts `None` for a new object. Tests: `BasicStorage.testSerialIsNoneForInitialRevision`, `RevisionStorage.testLoadBeforeConsecutiveTids`, `MTStorage.test2StorageThreads`, `test4ExtStorageThread`, `test7StorageThreads`. After an MTStorage failure, the other threads of the test wait in `tpc_begin` without end, so the acceptance test hangs instead of failing.
2. `getTid` is not a method of `zoe serve`: the server closes the connection with "unknown method getTid". The specification lists `getTid` as a required read method. Test: `BasicStorage.testGetTid`.

Both fixes are in `crates/zoe-server/src/protocol/session.rs`, outside the scope fence.

## What was tried

A probe patch, not committed, of `session.rs`: `storea` takes a nil serial as `z64`, and `getTid(oid)` returns the serial of the current record or `POSKeyError`. With it, the 39 tests pass, and both acceptance tests and the unit tests pass on CPython 3.12, 3.13, 3.14 and 3.14t (17 passed on each). The patch:

```diff
+            "getTid" => self.get_tid(args),
...
+    fn get_tid(&mut self, args: &[Value]) -> Result<Value, Fault> {
+        let [oid] = arity::<1>(args, "getTid")?;
+        let oid = Oid(u64_of(oid)?);
+        match self.store.load_before(oid, Tid(u64::MAX))? {
+            Some(record) => Ok(p64(record.serial.0)),
+            None => Err(Fault::of(&ZoeError::NotFound { oid })),
+        }
+    }
...
-            let (oid, serial) = (Oid(u64_of(oid)?), Tid(u64_of(serial)?));
+            let (oid, serial) = (Oid(u64_of(oid)?), optional_tid(serial)?.unwrap_or(Tid(0)));
```

A real fix also needs: `getTid` of a deleted object, `getTid` against the published tid (as `loadBefore` does), Rust unit tests, and the specification row of `storea`.
