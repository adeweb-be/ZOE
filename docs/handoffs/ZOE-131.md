## The open difference: `checkBadMessage1` and `checkBadMessage2`

The server closes a connection on a frame that is not a call, as ZEO's server does. The cause of the failure is in the client process, not in the close.

The client log of the planner run 38617068770 (CPython 3.12) shows, for each failed run: `connection_lost ... BrokenPipeError`, `disconnected`, `try_connecting`, and then no `connection_made` until the teardown cancels the connect ("Connection to ... cancelled"). The server accepted that new TCP connection: it logs a reset of a new client port at the teardown. So the kernel completed the connect, and the event loop of the client never saw it. Each failed test took about 8 seconds: two waits of 4 seconds (`wait_timeout=4` of the test client) in the two `tpc_abort` calls.

The mechanism, in CPython 3.12 `asyncio/selector_events.py`:

1. The first `_dostore` after the bad frame writes `tpc_begin`, `storea` and `vote`. A write fails with `EPIPE`, so `_force_close` marks the transport lost (`_conn_lost`).
2. `_SelectorSocketTransport.writelines` of CPython 3.12 has no `_conn_lost` check (3.13 and 3.14 have it). A later write of the same burst appends to the buffer, `_write_sendmsg` returns at once, and `writelines` registers the file descriptor for write in the selector. `_call_connection_lost` then closes the socket and leaves that registration.
3. The reconnect creates a socket. It gets the same descriptor number. `sock_connect` calls `_add_writer`, finds the stale key with the same events, and changes only its data: no `epoll_ctl`. The new socket is not in epoll, so the connect never completes.

ZEO's server is slower to close: it reads the burst of the client with the bad frame in one `recv`, logs a traceback, then closes with a clean FIN while the client waits for its vote. The client then writes nothing to a lost transport. `zoe serve` closes within the burst.

On CPython 3.13, 3.14 and 3.14t the guard of `writelines` prevents step 2. The nightly recipe stops at the first interpreter that fails, so no run showed these tests on 3.13 or later yet.
