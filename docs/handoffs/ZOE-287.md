# ZOE-287: handoff

## State

The mirror serves KeywordIndex, DateIndex, DateRangeIndex, BooleanIndex and UUIDIndex, and `zoe.plone.catalog` builds their clauses (`v`, `b`, `d` of ADR 0059, section 8). The acceptance tests of the card are written and green locally: `crates/zoe-catalog/tests/indexes.rs` (8 tests, on `tests/data/indexes.json` that `tests/data/indexes.py` writes with Products.ZCatalog 7.2.1) and `python/zoedb/src/zoe/plone/tests/test_catalog_indexes.py`. `tests/data/zcatalog.py` adds an `OOBTree` whose root has inner nodes as children, so `tree_record` is compared with CPython bytes for an inner child.

## What blocks

One assertion block of the acceptance test of ZOE-286, `crates/zoe-catalog/tests/mirror.rs`, `an_option_that_the_mirror_does_not_serve_gives_a_refusal`, fails, and only an edit of that test makes it pass. Its model declares the index `Subject` with the class of a KeywordIndex as an index that the mirror does not serve (`IndexKind::Other(KeywordIndex)`), and expects `index_unavailable` for a clause and for a sort on it. With this card the mirror serves a KeywordIndex: the clause gives an empty result, and the sort gives `sort`.

The proposed edit, which keeps the intent of the test: in `model_with` of `tests/mirror.rs`, give `Subject` the class of an index that stays out of the mirror, such as `IndexKind::Other("Products.ZCTextIndex.ZCTextIndex", "ZCTextIndex")`. The assertions then hold as written. The builder did not make the edit: `tests/mirror.rs` is an acceptance test outside the scope fence.

## Next step

When the edit of `tests/mirror.rs` is accepted, make it, run `cargo test -p zoe-catalog`, open the pull request, and post the run of `just plone zoe backends -t catalog` in it.
