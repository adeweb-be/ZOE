## What fails, and why

The probe (`tests/scripts/locust_probe.py`) reports `ru_maxrss` of `getrusage(RUSAGE_SELF)`. On Linux this value keeps the peak of the parent across `execve`: the kernel copies the peak of the old memory map into the process at exec (`setmax_mm_hiwater_rss(&tsk->signal->maxrss, old_mm)` in `exec_mmap`), and `subprocess` starts the child with `vfork`, so the old map is the map of pytest. The fixture `written` of the module plans `xlarge` in the pytest process, about 0.93 GB. So each probe reports about 1.0 GB, whatever Locust uses.

Evidence:

- From pytest: `maxrss_bytes` 1,049,358,336 to 1,049,788,416 in the 12 cases, with `start_seconds` 0.23 to 0.35 s.
- The same probe, the same files, from a shell: 60 to 70 MB (`browse` 61 MB, `edit` 70 MB, `mixed` 61 MB, `workflow` 65 MB, `create-spread` 60 MB, `warmup` 62 MB).
- A child of a Python process that peaked at 900 MB: `ru_maxrss` 912 MB, `VmHWM` 11 MB.
