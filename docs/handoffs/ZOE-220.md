# ZOE-220 handoff

## State

- Branch `card/ZOE-220` (PR #463, draft) holds the three steps of the card. The acceptance test `python/zoedb/src/zoe/plone/tests/test_queued_indexing_mounted.py` is green, and so is `just plone zoe backends` (59 tests).
- Step 1, after the human approved the text of ADR 0047 §4 and question 12: each thread of `zoe.plone.indexing` searches the sites of its own database. The thread of the root database searches the top of the Zope root. The thread of a mounted database searches at and just below the mount points that `_mount_paths()` gives to its database. `_mount_paths()` now gives `(path, database name)`. Each site still goes to the thread of the database of its catalog. `_services` and `_root` keep their names, so the helper `stop_threads()` of the acceptance test did not change.
- Step 2: `test_indexing.py` tests the search of each thread (with a patch of `_mount_paths`), a mount point of another database, `IDatabaseOpenedWithRoot` with one thread for each database and the queues of both sites applied with no wake, a root on a FileStorage that starts only the mounted thread, and a failing site that leaves the others served.
- Step 3: a site whose `_serve` fails waits before its next try (0.4 s, doubled at each failure, up to `BACKOFF`, 30 s). `_cookie_path` takes the path from the first `-/`, so a path with a dash works. The docstring of `Indexer.run()` says what it counts. The comment on a cookie from the future no longer names one process.
- The observation from B5 on the card (two batches of the indexer insert the same key in a catalog `IIBucket`): no log of those runs is kept on this machine. The code explains it. Two processes can take one free lease at once (both read no lease, both write). Each one then ran a whole `run()`, up to 50 batches, and did not read the lease again. Both scan the same first keys, so their batches write the same entries, and the vote of one fails. This is the case of ADR 0047 §3 and §4: two holders cost a conflict, not a wrong catalog, because a path applied twice gives the same entry. The ADR did not change. The indexer of a thread now reads the lease before each batch and stops when it holds the token of another thread. This shortens the overlap to one batch.
