## Notes for the next session

- The machine runs other jobs on the default ports of B5: use `--port-offset 200`.
- The machine sleeps when nobody uses it, and a sleep spoils a run: run a long campaign under `caffeinate -ims`. A run whose Locust history has fewer rows than its seconds slept.
- B6 matches each transaction of a log to a request by time. So it gives each batch of the indexer thread the start of a request that was in flight, and it replays batches that ran one after the other as concurrent. A replay that starts the transactions with the note `zoe.plone: indexing queue` at their commits gives 1.9 `ConflictError`s per 1,000 transactions on both stacks. That change of `bench/replay` is outside the scope fence of this card; a later card can make it.
- The tests of mounted databases put a second `zoe.Storage` database in the databases of the database of the layer, with a cross-database reference from the Zope root, as a mount point does. No scenario under `plone/` mounts a ZOE store, so no instance with `Products.ZODBMountPoint` ran the backend.
- The scripts of the spike and of the measures are outside the repository, as the spike says. `zoe serve` writes a resolution log only with `--resolution-log`: the runs set `ZOE_BINARY` to a script that adds the option.
