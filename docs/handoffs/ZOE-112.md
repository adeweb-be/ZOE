## State

- Branch `card/ZOE-112` holds a merge of `origin/main`, a layout-only `cargo fmt` of the acceptance test, and the change.
- `continues` and `compare` in `crates/zoe-convert/src/backup.rs` compare the pack watermark with `>`. The texts of `BackupPacked` and of the difference say "after the last tid". ADR 0030, the specification and `crates/zoe-convert/CLAUDE.md` state the rule.
- The unit test `records_that_a_pack_removed_are_no_difference` packs at the last tid of the dumps (the backups go on, no difference), then after it (`BackupPacked`, one difference). It passes.
- `just check` passes.
- The acceptance test `crates/zoe-server/tests/backup_pack.rs` passes up to its last part, and fails there. The failure is in the test.

## The failure

The last part of the acceptance test commits the root again at `later` and packs at `later`:

    let later = {
        let store = common::open(&source);
        commit(&store, &[(ROOT, next, record(b"4"))])
    };

The transaction `next`, the last tid of the dumps, holds only the root. The pack at `later` removes that record of the root, because the root has a newer record at or before the pack tid. The pack then removes the transaction row of `next`, because the row keeps no record (`remove_txn` in the pack of `zoe-core`). So the last tid of the dumps is not a tid of the store, and `zoe backup` refuses with `BackupDiverged` ("their last tid ... is not a tid of the store"), not with `BackupPacked`. The test expects "the store was packed at tid".

The same happens on `main`: the card does not change the check order in `continues`.

## Tried

The edit below, applied locally and then reverted, makes the whole acceptance test pass with the change of this card:

    let later = {
        let store = common::open(&source);
        let other = store.new_oid().unwrap();
        commit(&store, &[(other, Tid(0), record(b"4"))])
    };

The commit stores an object that the root does not reach. The pack at `later` removes that object, and keeps the record of the root at `next`, so the transaction `next` stays in the store. The pack watermark and the last tid of the store are both `later`, because the last tid is kept in `meta`.

## Not done

The other way is to change `continues` so that a missing last tid with a pack watermark at or after it refuses with `BackupPacked`. That changes `BackupDiverged` for a store restored from a part of the dumps and then packed, and for another store packed after the dumps (two unit tests assert `BackupDiverged` there). The card says that `BackupDiverged` stays as it is, so this was not done.
