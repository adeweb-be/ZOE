## The bug in the acceptance test

`test_kill_loop.py` gives each writer the seed `(run, w)`, a tuple. `random.Random` accepts only None, int, float, str, bytes and bytearray since CPython 3.11, so each writer thread raises `TypeError` at its first line. No commit is acknowledged, and the test fails with `AssertionError: no commit was acknowledged`.

The edit that the test needs, line 111:

```diff
-                    args=(server, tmp_path / f"cache-{w}", (run, w), done, outs[w]),
+                    args=(server, tmp_path / f"cache-{w}", f"{run}-{w}", done, outs[w]),
```

## What was tried

A copy of the test with only this edit, outside the repository, against the debug `zoe` binary of the branch, on CPython 3.13:

- 20 rounds, seed 1: 1 passed in 11.45 s.
- 200 rounds, seed 86: 1 passed in 281 s; 1,607 acknowledged commits, 121 of them blobs, 0 lost, `zoe verify` clean after each round.

## Open question: 10,000 rounds

Each round loads every commit acknowledged since round 0, so the time of a round grows with the round number. On this machine a round takes about 0.5 s plus 9 ms per earlier round. 10,000 rounds then take about 450,000 s, which does not fit a nightly job. A test that checks only the commits of the current round, or the whole set every N rounds, keeps a round near constant. That is also an edit of the acceptance test, so the human decides.
