# Handoff: ZOE-165

## State

The branch `card/ZOE-165` holds the acceptance test (unchanged) and the merge of `card/ZOE-162`. The native inside is the default of `zoe.zeo.ClientStorage` and `<zoeclient>`; `native=False` and `native false` keep ZEO's asyncio client. A subclass of `zoe.zeo.ClientStorage` keeps ZEO's client by default, because it can change its methods.

What the card fixed in the client, each found by a run of the acceptance test:

- `zoe.testing.NATIVE_LAYER` gives `_NativeClientStorage` as base to each class of a loaded module that derives from `ZEO.ClientStorage.ClientStorage` (`TestClientStorage` of `ConnectionTests`, `ServerManagingClientStorage` of `testZEO`). Before, their `__init__` ran the native `__init__` on a ZEO instance, and 56 tests of `testConnection` and the blob doctests of ZODB failed. Now `testConnection` runs on the native client.
- Each connection calls `notify_connected(conn, info)` and each loss `notify_disconnected()`, as ZEO does. `conn` is a `_NativeConnection` with `get_peername()`, `protocol_version`, `is_read_only()`, `call_async` and `verify_result` in the words of ZEO.
- `_server` is a `_NativeServer`: `call`, `async_`, `is_connected`, `is_read_only`, `timeout` and `client` (the last connection). `_cache` gives `maxsize`, `path`, `len()`, `contents()` (new `Cache::entries` in Rust, `Client.cache_entries` in the binding) and `clear()`.
- A call that needs the server waits for one at most `wait_timeout` (or the `timeout` of `_call`), as ZEO does, then raises `ClientDisconnected`. This removes a departure that the spec listed. `_wait()` is ZEO's.
- The client logs its connections, losses, dropped caches and refused servers under `ZEO.ClientStorage`, with the words of ZEO, and the errors of the server that ZEO logs under `ZEO.asyncio.client`.
- `load` and `loadBefore` raise a server error as ZEO does (a `POSKeyError` keeps its oid as bytes).
- `storeBlob` takes a str serial, as `store` does.
- A `ConflictError` of a stock server keeps its `class_name` (new field of `zoe_client::Error::Conflict`), so its text names the class of the object.
- `ClientStorage(port)` gives the name `('127.0.0.1', port)`, as ZEO.
- A server of another protocol (`Z4`, or `Z5` without `msgpack true`) is a failed connection, as for ZEO: the open logs "Registration or cache validation failed, b'Z4'" under `ZEO.asyncio.client`, tries again after 9 seconds, and raises `ClientDisconnected("timed out waiting for connection")` at the end of `wait_timeout` (new `zoe_client::Error::OtherProtocol`). `protocols_test` passes against a stock ZEO server (driver run of `testZEO`, filter `protocols`).
- The `StaleCache` event and the critical log come before the drop of the cache, at a reconnect and at the verification of a file at the open, as ZEO does (new `Reconnect::dropping` in `zoe-client`, `dropping=` and `ready(timeout)` in the binding). `drop_cache_rather_than_verify_txt` passes against `zoe serve`.

Run of `test_zeo_suites_native.py::test_the_suites_of_zeo_pass_with_the_native_client_against_zoe_serve` on CPython 3.13: 126 problems. 96 are `FileStorageSSLTests` and `SSLConnectionTests`; the 30 others are below. Against a stock ZEO server, the run stops early: the SSL tests fail in `setUp` and leave the current directory nested, until a path is too long. A run module by module against a stock ZEO server gives the same list, plus `checkCommitLockVote*` of `FileStorageLoadDelayedTests` and `TimeoutTests.checkTimeoutAfterVote` (item 2). `client_asyncore_thread_has_name` (item 6) fails in a run of `testZEO` alone, and passed in the run of the whole module list, where a test before it leaves a thread of ZEO's client open.

## Blocked on

The coordinator took items 1 to 4, 6 and 8 to the human. Items 5 and 7 are fixed (see "State").

Each remaining test fails for a decision that a card or the human took before, or because it reads the asyncio inside of ZEO's client. None can pass without a change of such a decision or a stand-in. `OUT` is the planner's, so each needs a decision: an entry of `OUT`, or a card that changes the decision.

1. **An `ssl` context.** The human decided (ZOE-158) that the native client takes only the files of `<ssl>` of `<zoeclient>`, and that an `ssl` context fails the open. ZEO's tests give a context: `FileStorageSSLTests` (all of it, a class that the card names), `SSLConnectionTests` (all of it), `quick_close_doesnt_kill_server`, and `SSLConfigTest.test_ssl_basic` and `test_ssl_hostname_check`. Also, `server.pem` of ZEO's tests is self-signed, and the native TLS refuses it (a known limit of `zoe-client`). Options: `OUT` for these, as `test_native_transport_suites.py` did; or a card for TLS from a context (the CA certificates come out of `get_ca_certs(binary_form=True)`, but no public API gives the certificate and the key of the client) and for a server certificate that matches a certificate of `authenticate` by its bytes.
2. **The pool of connections (ADR 0036).** `CommitLockVoteTests.checkCommitLockVoteAbort`, `checkCommitLockVoteClose` and `checkCommitLockVoteFinish` (in four classes) send `vote` of a transaction with `_server.call('vote', id(txn))`: on the native client, the transaction is on its own connection, and the listener never runs a call of a transaction. `test_ruok` and `test_server_status` expect `'connections': 1`; the native client has the listener and one connection that committed, 2. Against a stock ZEO server, `TimeoutTests.checkTimeoutAfterVote` expects the timeout of a transaction to close the one connection of the client; only the connection of the transaction closes.
3. **The `.zoec` cache file (ZOE-162).** The native client never reads or writes ZEO's `.zec` file. `InvqTests.checkQuickVerificationWith2Clients` waits for `test-1.zec`; `client-config_test` reads `_cache.path == 'cache-2.zec'` (and the class name `ClientStorage`); `ZEOConfigTest.test_client_variations` reads `_cache.path == 'test'`; `invalidate_client_cache_entry_on_server_commit_error` writes a bad `.zec` file with `ZEO.cache.ClientCache` and expects the client to read it.
4. **A cache file serves only after its verification (ADR 0034).** `checkBasicPersistence`, `checkDisconnectedCacheWorks` and `checkDisconnectedCacheFails` (two classes each) open the client with `wait=False` and no server, and load from the cache file. ZEO serves a cache file that it did not verify; ADR 0034 does not.
5. Fixed: the `StaleCache` event comes before the drop.
6. **The asyncio inside of ZEO.** `checkBadMessage1` and `checkBadMessage2` (two classes) write a message through `_server.client.protocol` on `_server.loop`; `checkCatastrophicClientLoopFailure` stops `_server.loop` and joins `_server.thread`; `checkConnectionInvalidationOnReconnect` calls `connection_lost` of `_server.client.protocol`; `tpc_finish_error` takes the `TransactionBuffer` of `_check_trans` and sets `client_resolved`; `test_ZEO_client_convenience` gives a mock of ZEO's client thread as `_client_factory`; `client_asyncore_thread_has_name` expects ZEO's networking thread, which the gate itself asserts does not start.

7. Fixed: `protocols_test`.
