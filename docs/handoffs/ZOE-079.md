## Question on the card (stop and ask)

The Python acceptance test needs `zoe.Storage.deleteObject`. This is a public Python API that the card does not name. It also needs `Txn::delete` in `crates/zoe-core/src/commit/`. Both are outside the scope fence. Options:

- (a) Make this card depend on ZOE-052 (`Txn::delete`), and widen its fence to `crates/zoe-py/src/storage.rs` for `deleteObject` alone. Recommended: `Txn::delete` keeps one owner.
- (b) Widen the fence to `crates/zoe-core/src/commit/**` and `crates/zoe-py/src/storage.rs`, and add both here.
- (c) The human changes the acceptance test to make the deletion with `restore` in a restore transaction. `zoe.Storage` has `restore`.

A second point: `verify` does not check the sequence rows. No read of the store lists their names. A new `Backend` method `sequence_names` in `backend.rs` and `redb_backend.rs` would list them. The standing rule allows new `Backend` methods, but these files are outside the fence.

- `crates/zoe-convert/src/lib.rs`: `mod verify` and its exports.
