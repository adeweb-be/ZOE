# Handoff: ZOE-124

## State

PR #264 implements the card: deferred restores, `Store::sync`, `WriteTxn::commit_deferred`, `Backend::sync` as a real barrier, and the batched syncs of `from_datafs`. CI passes every test except one acceptance test: `a_crash_loses_only_the_open_batch_and_the_conversion_resumes` (`crates/zoe-convert/tests/batched_sync.rs`) fails at line 331, `assert!(report.problems.is_empty())`.

Every assertion before line 331 passes:

- The store ends at transaction 1,999.
- No blob file of a lost restore stays, and `blobs/tmp/` is empty.
- The resumed conversion copies 1,000 transactions.

## Cause

The report of the resumed conversion has two problems, one for each blob: "the blob file of the store: No such file or directory". The verification pass (`check_blob` in `crates/zoe-convert/src/datafs.rs`) checks the size of each blob file with `std::fs::metadata(store.blob_path(..))`. The test store is on `MemVfs`, and `MemVfs::path` gives a relative path such as `blobs/0x00/.../0x...blob` that does not exist on disk. So any `MemVfs` store with blobs gets these problems from the verification, with or without this card. The test needs `MemVfs` for `kill_at_dir_sync` and `crash_now`, so it cannot use a store on disk.

## Tried

Nothing in the code. The card puts the verification pass out of scope ("the verification and the report do not change") and allows no new public API in `zoe-core`. A size check through the store's `Vfs` would need both.
