# zoe-pickle

Decode and encode ZODB records (the class pickle and the state pickle) as a generic tree. Specification: "Loupe", section "Pickle layer".

## Invariants

- Decode then encode gives the same bytes, for every record of the corpus and for every record that the decoder accepts.
- A construct that the tree does not model becomes an opaque node that re-emits its original bytes. An edit inside an opaque node is refused.
- Class names come from reading the class pickle, never from unpickling state.
- The encoder writes the opcode form that each node keeps, also the protocol-0 and protocol-1 forms of Python 2 stores. It never picks another form. Nodes for new values use protocol 3 with ZODB's `persistent_id` convention.
- Decode, encode, drop, clone, comparison and debug never call themselves once per nesting level. They use explicit stacks in the heap. Any new operation on a tree does the same.
- The decoder copies the bytes of each opaque span once: it records spans while it runs and copies the spans that remain at the end.
- A record has a node budget. `decode_record` uses `NODE_BUDGET` (2²⁰ nodes), for online readers such as Loupe. `decode_record_with` takes the budget as a parameter, in `Limits`. The decoder refuses a record that needs more nodes with `Error::Budget`, which is not `Error::Decode`: the bytes can be valid.
- Offline tools that must read every record, such as pack and the converters, give a budget equal to the length of the record. The node count never gets above that length, so this budget refuses nothing that the input can hold. For these tools, any refusal is a hard error. Pack never reads a refused record as a record with no references.
- At a budget equal to the record length, the memory of the tree grows with the record: up to about 150 bytes per byte of record. Pack and the converters read one record at a time for this reason.
- `persistent_ids` is equivalent to ZODB's `referencesf`: it gives the persistent id of every BINPERSID and PERSID of both pickles, in pickle order, with each repeat, the parts inside opaque nodes included. It decodes the record first with a budget equal to its length. A refusal of the decoder, a persistent id that is not a string, a tuple that starts with a string, or a list, and a text oid that is not ASCII are errors. It never guesses: a caller must not read such a record as a record without references. Its tests compare it with `referencesf` on the corpus and on hand-built records.
- `persistent_ids` does not read the tree. A small stack machine runs over the opcodes, as the `noload` of `referencesf` does, and keeps tuples and lists in arenas, so a deep value cannot overflow the call stack.
- `decode_class_name` decodes the class pickle alone and stops at its end, so a large state costs nothing.
- A memo get resolves to the latest put of its index before it, across the class pickle and the state pickle. A put inside an opaque node hides the value of its index.
- The decoder refuses the bytes that Python's unpickler refuses as malformed, for example an unknown protocol or a BINSTRING or LONG4 length of 2³¹ or more. It can refuse more, for example a pickle that leaves values on the stack at STOP. An error that Python finds only when it calls a class or a function, for example REDUCE with arguments that are not a tuple, stays inside an opaque node.

- `python` models the objects that Python's unpickler builds from a record, in a `Heap` whose objects refer to each other by index. Each opcode that makes a str, bytes, tuple, list or dict makes a new object, and a memo get gives the object of its put, across the class pickle and the state pickle. The heap shares what CPython and ZODB's resolver share: the empty str and each str of one character below U+0100, the empty bytes and each bytes of one byte, one class object for each module and name, and one persistent reference for each persistent id across the records of one resolution. A test of each sharing reads the identity from CPython (`a_state_pickles_to_the_bytes_that_it_came_from`, `short_strs_and_bytes_are_shared_across_records`).
- The pickler of `python` writes as the C pickler of zodbpickle with protocol 3: PROTO 3 and STOP for each dump, one memo for the dumps of one pickler, a memo get for an object that it saw, BINUNICODE, SHORT_BINBYTES or BINBYTES, the int forms of `save_long`, BINFLOAT, a tuple of up to three items with TUPLE1 to TUPLE3, a dict of one item with SETITEM and other dicts in batches of 1,000 with SETITEMS, followed by an empty batch after a full one, a list of one item with APPEND and other lists in batches of 1,000. A persistent reference writes its persistent id, then BINPERSID, and never goes into the memo.
- The comparisons of `python` are those of Python and of `object_compare` of BTrees. Two lists compare as two tuples, but lists of different lengths are never equal. A comparison that the model cannot make is `Undecided::Unknown`; a comparison where Python raises for sure (a persistent reference against another object) is `Undecided::Raises`. The model refuses with `Unsupported` what it does not model: an opaque node, a REDUCE, a Python 2 str, a protocol 0 unicode, list or dict, an int beyond 128 bits, a dict key that is not an int, a str or bytes, a persistent id of an unknown shape, a container that holds itself. `Heap::dict_key` gives the key of a dict key that the model keeps (`DictKey`): keys of one kind are in the order of Python, and two keys are one key of a Python dict when they are equal.
- The loader, the comparisons and the pickler of `python` use explicit stacks, so a deep value cannot overflow the call stack.
- A heap of `Heap::with_instances` also models an object that NEWOBJ or REDUCE makes, with the state of BUILD (`Object::Instance`), and a set or a frozenset (`Object::Set`). It reads them from opaque nodes with a small loader over their opcodes and the memo of the record. A list, a dict or an object takes its items or its state only right after it is made, and a memo get of a value that is still being built is refused, so no value holds itself. It refuses a REDUCE of `copy_reg._reconstructor`, which Python 3 pickles again with NEWOBJ. It interns the str keys of a dict state, as `load_build` and `Persistent.__setstate__` do. It also keeps a dict key that is a tuple of ints, strs and bytes; a tuple in a tuple, a bool or a float in it stays refused. The default heap refuses tuple keys, so tier 1 does not change. The pickler writes such an object as `save_reduce` does: the class or the callable, the arguments, NEWOBJ or REDUCE, the put, then the state and BUILD; a set as REDUCE of its class with a new list. The default heap refuses these objects, as tier 1 needs. `Heap::eq` and `Heap::lt` give no answer for these objects. `Canon` gives each value a canonical id from its kind and the ids of its parts, a set with its item ids in order, so two values of the same structure have one id: it walks each object once with an explicit stack, and its shapes hold ids, not shapes, so their hash, comparison and drop never recurse. Past its step budget it gives `Undecided::Budget`. `Heap::set_budget` gives the comparisons of a heap a budget of steps in all; past it, `eq` and `lt` give `Undecided::Budget`. The loader of opaque values keeps the place of each key of a dict that it fills and a count of the fillable objects on its stack, so it runs in linear time.
- `btrees` names the classes of the families of BTrees but `fs`, and `BTrees.Length.Length`, and reads and builds the states of buckets, sets and BTrees of one inline bucket on the model of `python`, as their `__getstate__` gives them. A key or a value of an int family is what the C bucket keeps, so a float value goes through a C `float`.

## Known differences from Python

- `python` keeps a GLOBAL as its module and name. ZODB's resolver writes a class again with its `__module__` and `__qualname__`, so an alias of a module that the record names gives other bytes there, and a class that the resolver cannot import becomes `(module, name)` in a persistent id. The objects that both records give are the same. A merge of tier 1 is the record of a resolver that imports every class of the record under the name that the record gives.

- A dict key that Python cannot hash, such as a list, stays modelled. Python refuses such a record when it loads it, so no store holds one.
